## 二、产品定义

### 2.1 产品目标（一句话）
在不破坏移动端既有视觉/行为（保真红线）的前提下，用一套代码把 Nijapl 从「固定 420×860 手机竖屏窗口」升级为**移动端原生化 + 桌面端真正响应式**的多平台学习应用，并统一到 Tailwind CSS 4.x 维护。

### 2.2 可衡量目标
1. **五端可产出**：同一代码仓在 macOS/Windows/Linux/iOS/Android 均能构建出可运行产物，iOS 模拟器跑通核心学习闭环（Home→StageMap/Study→学习/复习/自测）。
2. **样式 100% 迁移**：存量 `.css`/`rpx` 业务样式全部迁入 Tailwind 4.x（含 design token），仓库不再遗留 Lynx 时代样式文件，构建零报错。
3. **移动端保真零违规**：核心页面在移动端与原 Lynx 实现逐屏一致（含反直觉行为），叠加的平台层适配（安全区/44px/常亮/TTS）不改动原有视觉与行为。
4. **PC 端真响应式**：最小/默认/最大化三档窗口下布局自适应，侧边栏导航 + 内容居中限宽 + 指针/hover 交互可用，无横向滚动与错位。
5. **性能软指标**：移动端页面切换 < 200ms、首屏可交互 < 2s（iOS 模拟器基准）。

## 三、用户故事

| 角色 | 需求 | 价值 |
|---|---|---|
| 移动端学习者 | 作为通勤用手机背词的用户，我要按钮≥44px、顶部避开刘海、底部避开 Home 条 | 单手自然操作、内容不被遮挡 |
| 移动端学习者 | 作为长时间学习用户，我要学习/自测时屏幕常亮、答题/翻卡有轻触觉反馈 | 学习不被打断、操作有确定感 |
| 移动端学习者 | 作为跟读用户，我要单词/例句用系统原生发音（Mobile.Speak 优先） | 发音准确、离线可用 |
| 桌面端学习者 | 作为在电脑上学习的用户，我要宽屏下内容居中限宽、左侧侧边栏快速切换模块（Home/Study/语法/图谱/我的） | 少点返回、导航高效 |
| 桌面端学习者 | 作为用鼠标的用户，我要 hover 有反馈、可悬停预览注音/释义 | 符合桌面操作习惯 |
| 维护者 | 作为开发者，我要全量样式统一到 Tailwind 4.x + 设计 token | 一套代码多端一致、改主题/字号成本低 |

## 四、需求池

### P0（必须有）
1. Tailwind CSS 4.x 接入 + 存量 `.css`/`rpx` 全量迁移为 utility/token。
2. 响应式断点体系 + 内容居中限宽 + PC/移动端差异化布局骨架。
3. PC 侧边栏导航落地（Home/Study/StageMap/Review/Grammar/Graph/Me/Kana 分组）。
4. 移动端安全区避让（`viewport-fit=cover` + `env(safe-area-inset-*)`）。
5. 移动端 44px 最小触控区 + 指针/触控交互区分（hover 仅在 `(pointer:fine)`）。
6. 五平台可构建（Wails v3 mobile，参考官方 `v3/examples/mobile` Kitchen Sink）。
7. iOS 模拟器验收流程跑通（构建→安装→跑核心闭环）。
8. TTS：移动端 `Mobile.Speak` 优先，桌面端用系统 TTS 兜底。
9. `rpx`→Web 单位映射规则（750rpx=逻辑视口宽 → rem/token），建立设计 token 基准。

### P1（应该有）
1. 移动端触觉反馈（答题对错/翻卡/切页轻震，native bridge）。
2. 移动端学习/自测页面常亮（wakelock）。
3. PC 窗口默认/最小尺寸 + 记忆上次位置与大小。
4. PC hover 态 + tooltip（卡片/导航/词条悬停预览）。
5. PC 窗口拖拽缩放到窄屏时降级为单列布局（响应式回退）。

### P2（可以有）
1. PC 宽屏两列布局（如语法列表 + 详情并排）。
2. 桌面端键盘快捷键（切页/翻卡/收藏）。
3. 移动端分享/截图保护/生物识别（**本次暂缓**，仅留扩展位）。
4. 深浅色主题。

## 五、PC / Mobile 差异化 UI/UX 设计（重点）

### 5.1 设计原则
- **移动端 = 保真**：保留原入口与页面结构（Home 为入口、无底部 Tab 的原始导航），仅叠加「平台层适配」，不新增导航、不改视觉/行为。
- **PC 端 = 新增响应式**：原桌面只是「手机竖屏窗口」，本次为其设计真正的宽屏布局，最大化复用原移动端组件，降低保真与开发成本。
- 用 CSS 媒体能力 `(pointer:fine)` / `(hover:hover)` 区分指针与触控，而非仅靠宽度。

### 5.2 断点与布局骨架
| 断点 | 布局 | 说明 |
|---|---|---|
| < 768px（移动/窄窗） | 单列全宽 + 安全区 | 等同原 App（420 列），移动端保真 |
| ≥ 768px（PC/宽窗） | 左侧栏 + 内容居中限宽 | 新增 PC 形态 |

### 5.3 PC 端设计
**① 导航形态推荐：左侧固定侧边栏（约 220–240px）**
| 对比 | 侧边栏 | 顶栏 |
|---|---|---|
| 页面数 | 一级入口 8+（Home/Study/StageMap/Review/Grammar/Graph/Me/Kana 子域）纵向可完整容纳 | 8+ 项横向放不下，需汉堡/溢出 |
| 宽屏空间 | 左侧留白天然有空间，符合桌面学习类 App 惯例（如 Anki） | 顶部横向紧张 |
| 内容区 | 右侧内容可保持「手机列」居中，复用组件、保真成本最低 | 内容全宽拉伸，与手机列形态冲突 |
| 多级分组 | 天然支持 Kana 子域（Kana/KanaStudy/KanaQuiz）折叠分组 | 顶栏难承载二级 |
**推荐：左侧固定侧边栏**，图标 + 文字标签，支持 Kana 二级折叠；`<768px` 时侧边栏收起为抽屉或隐藏，回退原移动端入口。

**② 内容居中限宽**
- 内容列 `max-width ≈ 480px` 居中（贴近原 420 手机列），两侧留白 + 可做浅色底/装饰背景，**最大化复用原移动端布局、保真风险最低**。
- P2 可对个别页（语法/图谱）放宽到两列，其余保持居中。

**③ 窗口尺寸建议**
| 项 | 建议值 |
|---|---|
| 默认尺寸 | 1180×800（横屏） |
| 最小尺寸 | 900×640 |
| 记忆 | 记忆上次窗口大小与位置（P1） |

**④ 触控 vs 指针差异（重点）**
| 维度 | 指针（桌面） | 触控（移动/触摸屏） |
|---|---|---|
| 触发条件 | `(hover:hover) and (pointer:fine)` | 其余 |
| hover | 按钮上浮/阴影、卡片描边高亮、导航项底色、词条悬停显示注音/释义 | 无 hover |
| 触达 | 常规 36–44px 即可 | 最小 44×44（图标可视觉小、热区大） |
| 反馈 | hover + 点击态 | 按压态（active）+ 触觉反馈 |
| 提示 | tooltip 悬停展示 | 长按/无 tooltip，信息直接呈现 |

### 5.4 移动端设计
| 项 | 方案 |
|---|---|
| 安全区避让 | `viewport-fit=cover` + `env(safe-area-inset-top/right/bottom/left)`，顶部避开刘海、底部避开 Home 条 |
| 44px 触控区 | 所有可点元素最小 44×44；纯图标按钮可视觉小、命中区放大到 44 |
| 触觉反馈 | 答题对错/翻卡/切页轻震（native haptics bridge），P1 |
| 常亮 | Study/Quiz 页面保持屏幕常亮（wakelock），P1 |
| 缩放/字号 | 锁定 viewport、禁止双击缩放，文字按 token 统一缩放 |
| 导航 | 保持原入口不变（**不新增底部 Tab**，维持保真） |
