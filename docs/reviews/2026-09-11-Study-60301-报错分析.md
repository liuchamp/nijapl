# P2 学习页崩溃分析：`Can't find ui tag`（603 / 60301）

- 现象：首页正常，点击「开始学习 / 继续学习」后崩溃
- 报错：`{"error_code":603,"sub_code":60301,"error":"Can't find ui tag","node_index":"0","fix_suggestion":"LynxUI has not been created or the creation failed while updating"}`
- 分析日期：2026-09-11
- 结论状态：**已修复并验证**（typecheck 0 / 276 用例全绿 / build 425.1 kB），见 §7

---

## 1. 错误码的官方定义

| 项 | 值 |
| --- | --- |
| `error_code` | 603 = `EB_LAYOUT_UPDATE`（布局更新阶段错误） |
| `sub_code` | 60301 = `E_LAYOUT_UPDATE_UI_NOT_FOUND` |
| 含义 | 更新布局时找不到对应的 LynxUI；即**某个元素的原生 UI 没有创建成功** |
| Lynx 团队在 issue #267 中的解释 | 60301 的实际触发原因是**页面里出现了 Lynx 不支持 / 未注册 Behavior 的元素标签**（issue 中是 `<header>`；iOS 上更清晰的报错为 `No BehaviorController defined for class 'xxx'`） |

> 也就是说：不是 JS 逻辑错，而是**某个标签/元素在引擎侧没能创建出来**。

## 2. 定位：崩溃元素就在 `src/pages/Study/index.tsx`

### 2.1 点击后一定进入 P2（Study 页）

`src/pages/Home/index.tsx:92`

```tsx
catchtap={() => { if (target !== null) nav.goStudy(target.moduleId) else nav.goStages() }}
```

`selectContinueTarget()` 只要仓库里有 stage + module 就返回非 null（`data/build/modules.json` 有 10 个模块），
因此点击后**必然进入 P2 Study 页**，不是 P1 阶段地图。

### 2.2 Study 页是全项目唯一使用 `viewpager` 的页面

全量 grep 结果：

```
src/pages/Study/index.tsx:180  <viewpager  key={`pager-${pagerToken}`} initial-select-index={index} bindchange=...>
src/pages/Study/index.tsx:190  <viewpager-item key={cardWord.id} className="Study-item">
```

其余页面（Home / StageMap / GrammarList / Graph / Quiz / Me）只用到 `view / text / svg / list / list-item / scroll-view`——首页能正常显示说明这些基础元素都没问题。

### 2.3 `node_index: "0"` 与 DOM 结构完全吻合

`.Study-stage` 只有一个子节点，它就是 `<viewpager>`（父节点下 index 0）；
`<viewpager>` 的第一个子节点是 `<viewpager-item>`（也是 index 0）。
两者任一创建失败，报的 `node_index` 都是 `0`。

### 2.4 编译产物已确认 viewpager 真实下发

`dist/main.lynx.bundle` 中可见：

```
"viewpager"===l ? eQ(dl,{values:[u, e=>{s$.setCurrentIndex(e.detail.index)}], $0: s.map(...viewpager-item...)}, `pager-${f}`)
```

说明编译没问题，**是运行时创建失败**。

## 3. 三个叠加诱因（按可能性排序）

### ① 主因：`<viewpager>` / `<viewpager-item>` 在当前宿主未成功创建

- Lynx 官方元素表中 `viewpager` 是 **Limited availability**（Android / iOS / HarmonyOS / Web / 桌面均非 Full support），
  部分宿主构建（尤其桌面 Clay 版、裁剪版 LynxExplorer）**没有打包 viewpager 的 Behavior** → 引擎报 60301。
- 项目其实**已经写好了降级实现**（`<scroll-view scroll-orientation="horizontal">`），
  但被平台白名单挡住，无法在出问题的宿主上生效：

  `src/services/platform.ts:17`

  ```ts
  const NATIVE_PLATFORMS = ['Android','iOS','Harmony','windows','macOS','pc']
  ```

  只要 `SystemInfo.platform` 命中（macOS / windows / pc 也在内）就强制走 viewpager。

### ② 首帧「创建即销毁」：key 强制重建导致竞态

`src/pages/Study/index.tsx:65-72`

```tsx
useEffect(() => {
  studySession.beginStudy(moduleId)   // 会 setCurrentIndex(...)
  setRevealed(false)
  setPagerToken((token) => token + 1)  // ← key 变化，viewpager 被销毁重建
}, [moduleId])
```

时序：**挂载 viewpager#1 → 同一帧的 useEffect 立刻 +1 → 卸载 #1、挂载 #2**。
原生 viewpager 的 item UI 是异步创建的，"创建后立刻被移除/更新"是 60301 的经典触发场景；
若此时 `#1` 的 `bindchange` 回调回来并对已销毁元素下发更新，同样表现为 `Can't find ui tag`。

### ③ 官方要求的样式缺一项

Lynx 文档对 viewpager 的强制要求：

- `<viewpager>`：`width: 100%` + `display: flex; flex-direction: row` ✅（`.Study-pager` 已满足）
- `<viewpager-item>`：`width: 100%` + **`flex-shrink: 0`** ❌

`src/pages/Study/index.css:64` 的 `.Study-item` **缺少 `flex-shrink: 0`**，item 会被压缩，进一步放大创建/布局异常。

### 附：`initial-select-index` 曾越界（现已夹取，但仍建议防御）

`git log c27d092` 的提交信息是「进度行加 `Math.min` 夹取，避免冷启动续学显示 31/8」，
说明 `currentIndex` 越界真实发生过。现在 `startStudy` / `setCurrentIndex` 内部已有夹取，
但**首帧渲染时用的是未经夹取的 `state.runtime.currentIndex`**（`Study/index.tsx:48` → `initial-select-index={index}`），
跨模块续学仍可能拿到上一模块的残留序号，建议一并夹取。

## 5. 修复建议

### 方案 A（推荐）：默认走 `scroll-view`，viewpager 作为可选项

1. `slideModeFor` 默认返回 `'scroll'`；只有在宿主明确支持时才启用 viewpager（可用能力探测 + 失败降级）。
2. 去掉 `key={`pager-${pagerToken}`}` 的"重建式翻页"，改用官方支持的程序化翻页：

   ```ts
   lynx.createSelectorQuery().select('#study-pager').invoke({ method: 'selectTab', params: { index, smooth: true } }).exec()
   ```

   同时移除 `useEffect` 里的 `setPagerToken(+1)`，消除"创建即销毁"竞态。
3. `.Study-item` 补 `flex-shrink: 0`；`.Study-pager` 给显式高度，避免百分比高度解析为 0。

### 方案 B：保留 viewpager，但做加固

1. 渲染前夹取序号，全页统一使用：

   ```ts
   const safeIndex = Math.min(Math.max(index, 0), Math.max(words.length - 1, 0))
   ```

   用 `safeIndex` 作为 `initial-select-index`、`word` 取值、进度文案的唯一来源。
2. 同 A2、A3（去 key 重建 + 补 flex-shrink）。
3. 加页面级 ErrorBoundary / 错误兜底：捕获 60301 时自动切到 `scroll-view` 分支重渲染。

### 7.2 去掉首帧「创建即销毁」

`src/pages/Study/index.tsx`

- 删除 `useEffect([moduleId])` 里的 `setPagerToken(+1)`，容器**只创建一次**；
- 新增 `src/services/pagerSeek.ts`：用官方 UI 方法定位，不再靠 `key` 重建

## 8. 第二轮修复（2026-09-11 晚）：viewpager 全平台停用 + 三级降级

### 8.1 复现反馈推翻了上一轮假设

首轮把白名单收紧为「仅 Android / iOS / Harmony」后**仍复现**，且新错误里带出了
宿主真身：

```
error_stack: java.lang.RuntimeException: Trying to remove unknown ui signature: 809
  at com.lynx.tasm.behavior.PaintingContext.removeNode(:2)
  at android.os.MessageQueue.nativePollOnce(Native Method)
  at android.app.ActivityThread.main(ActivityThread.java:8857)
```

- `com.lynx.tasm.behavior.*` + `android.os.Looper` ⇒ **宿主是 Android**；
- 9902 `Trying to remove unknown ui signature` 是 60301 的**必然后遗症**：
  容器 UI 从未创建成功（没有 signature），返回上一页卸载时 `removeNode` 找不到它。

**结论**：`viewpager` 的 Behavior 在该宿主的 Lynx 构建里**根本没注册**。
官方元素表中 viewpager 属于 *Limited availability*，需要宿主单独注册；
「Android 就一定有」是错误假设，平台标识无法预测能力是否可用。

### 8.2 本轮改动

| 文件 | 改动 |
| --- | --- |
| `src/services/platform.ts` | 新增 `viewpagerEnabled` 全局开关（**默认 false**）与 `setViewpagerEnabled` / `isViewpagerEnabled`；`slideModeFor(platform, enabled = viewpagerEnabled)` 在开关关闭时**无条件返回 `scroll`**。白名单降级为"开关打开后的二次校验" |
| `src/pages/Study/index.tsx` | ①容器 `key` 绑定 `moduleId`（换模块才重建，同模块翻页只 seek）；②`scroll-view` 的每个直接子节点加 **`flatten={false}`**；③新增 `pagerFailCount` / `PAGER_FAIL_LIMIT = 2`：定位连续失败 2 次 → `containerBroken` → **单卡片降级**渲染 |
| `src/services/pagerSeek.ts` | `onUnsupported`（宿主无 SelectorQuery，**能力缺失**，只重建）与 `onFail`（有能力但 invoke fail，**容器 UI 未创建**）拆成两个回调，供上层区分处置 |
| `src/services/__tests__/platform.test.ts` | 改为「默认全平台 scroll / 开开关后移动端 viewpager / 开开关后桌面仍 scroll」 |
| `src/services/__tests__/pagerSeek.test.ts` | 新增 `onFail` 与「无 SelectorQuery 不算失败」2 例 |

### 8.3 两个易踩的 Lynx 细节

1. **`initial-scroll-to-index` 要求所有直接子节点 `flatten=false`**
   （类型定义原文：*"All direct child nodes must be flatten=false"*）。
   而 `<view>` 的 `flatten` **默认是 `true`**，不显式关掉会让索引定位失效。
2. **能力探测与失败要分开**：`lynx.createSelectorQuery` 不存在只说明宿主没这个
   API，不代表容器坏了；只有"有 API 却 invoke fail"才是 UI 未创建的强信号。
   混为一谈会把能用的容器误判成不可用。

### 8.4 三级降级链

```
<viewpager>  ──默认关闭（需 setViewpagerEnabled(true)）──┐
                                                        ├─→ 单卡片（按钮翻页，功能不缺）
横向 <scroll-view>  ──默认── 定位连续失败 2 次 ──────────┘
```
