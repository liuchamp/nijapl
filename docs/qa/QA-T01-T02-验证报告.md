## 三、发现的问题清单（按严重度排序）

### F1 ·【高】`conjugation.ts` 五段動詞「ない形」形态错误（未然形误用連用形）
- **文件/函数**：`src/engine/conjugation.ts` → `buildConjugationTable`，`五段動詞` 分支（约 L101）`${base}${iRow}ない`。
- **最小复现**：
  ```
  buildConjugationTable(のむ/五段動詞) → ない形 = "のみない"   （期望 "のまない"）
  buildConjugationTable(かく/五段動詞) → ない形 = "かきない"   （期望 "かかない"）
  buildConjugationTable(はなす/五段動詞)→ ない形 = "はなしない" （期望 "はなさない"）
  buildConjugationTable(まつ/五段動詞) → ない形 = "まちない"   （期望 "またない"）
  ```
- **根因**：`ない形` 复用了 `GODAN_I_ROW`（い段：う→い）。日语「ない形」须用**あ段**（未然形：う→わ、く→か、す→さ、つ→た、む→ま…）。缺失独立的 `GODAN_A_ROW` 表。
- **期望行为**：五段动词 `ない形 = 词干 + あ段音 + ない`。
- **影响面**：**全部五段動詞**（seed 中 `のむ/いく/きく/よむ/かく/はなす/つかう/まつ` 等）变形表对学习者展示错误形态。属 T02 范围内纯函数正确性缺陷。
- **修复建议（不改源码，仅供工程师参考）**：新增 `GODAN_A_ROW`（う→わ/く→か/ぐ→が/す→さ/つ→た/ぬ→な/ぶ→ば/む→ま/る→ら），`ない形` 改用 a-段；`ます形` 保持 i-段。

### F2 ·【低】`conjugation.ts` 五段不规则 `行く` 未处理
- **最小复现**：`buildConjugationTable(いく/五段動詞)` → て形 = `"いいて"`、た形 = `"いいた"`（期望 `"いって"` / `"いった"`）。
- **说明**：`行く` 是唯一 te/ta 特殊的五段例外；设计未要求例外表，属已知难点。建议至少加例外分支或文档标注局限。

### F3 ·【中】SRS 五态中「学习中」无任何引擎路径可达
- **证据**：从「未学」出发，`applySelfEval` 的三种自评结果集合为 `{已掌握, 模糊, 需强化}`，`applyReviewResult` 同；`applySkip` 输出 `未学`。**无任何函数产生 `state='学习中'`**。`SRS_STATES` 声明 5 态，实现实际产生 4 态。
- **依据**：PRD §5.5 将「学习中」列为独立状态（判定列写「首次作答」）。设计 §3.3 的 `initialProgress/applySelfEval/...` 亦未给出进入「学习中」的入口。
- **风险**：若 P1 节点五态徽章（T04）依赖「学习中」展示，将永不出现；`STATE_SCORE['学习中']=0.25` 亦为死代码。
- **判定**：**设计歧义**（可能为 UI 瞬时态，非引擎态）。非崩溃，交由架构/产品拍板；建议明确「学习中」由谁写入。

### F4 ·【低】J1 在 `selfEval` 缺省时仍会触发
- **证据**：`evaluate(ctx, 'selfEval')` 且 `ctx.selfEval === undefined`、`seen===false` → 命中 J1。
- **说明**：设计 §3.3 备注允许 `selfEval` 缺省退化，但意味着调用方**漏传** `selfEval` 时，即便用户选了「认识」也会自动展开详解浮层。属调用契约风险，建议调用方（T04 `studySession`）务必显式传入；或引擎侧对「仅当 selfEval==='不认识'」加严。

### F5 ·【低】`stages`/`modules` 记录无 `source` 字段
- **证据**：`stages 0/4`、`modules 0/10` 含 `source`；`words 50/50`、`grammars 16/16`、`sentences 19/19` 均 `source:'seed'`。
- **依据冲突**：PRD §7.2「每条数据标记 `source:"seed"`」 vs ARCH §3.1 `Stage`/`Module` schema **无 source 字段**（seed 注释亦声明设计如此）。当前实现遵循 ARCH schema。
- **建议**：以架构 schema 为准，提请 PM 收敛 PRD 措辞（或对 Stage/Module 也补 source）。不影响运行。

## 五、当前实现最脆弱、最该补测的地方（QA 建议）

1. **`conjugation.ts` 缺系统性形态测试**：现有工程师测试集**完全未覆盖** `conjugation`（无 `conjugation.test.ts`），导致五段 `ない形` 全错却全绿。这是本次最大盲区 → 必须补五段/一段/サ変/カ変 + 例外（行く、する复合）参数化用例。
2. **`SentenceWord` 偏移 ↔ `surface` 一致性未校验**：`validate.ts` 只查 `0<=start<end<=ja.length`，不查 `ja.slice(start,end)===surface`。偏移写错（指到别的子串）不会被拦截 → 建议加该校验（真实数据阶段尤其关键）。
3. **J1 的 `selfEval` 缺省语义**：建议以「必须显式 selfEval」为契约并加护栏测试，避免 T04 漏传导致误弹浮层。
4. **「学习中」状态契约缺位**：应在架构层明确由哪个动作写入，否则 T04 节点五态无法完整呈现。
5. **`graph/layout` 仅验证「不崩 + 确定性」，未验证布局质量**：如节点是否重叠、半径是否越界（坐标可落在画布外）。当前 `autoRadius` 在极端小画布下可能为 0 致节点重叠，建议补「坐标落在 padding 内」类断言。
6. **`overallCompletion` 的加权口径**：现为「各阶段完成度**等权**平均」，未按词量加权；阶段词量悬殊时口径可能失真，建议与产品确认权重定义。
